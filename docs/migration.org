* Upgrading to 1.0
:PROPERTIES:
:CUSTOM_ID: upgrading
:END:

The suite you have keeps running the way it did: a suite shuffles its tests by
default, exactly as before 1.0, and the seed of the shuffle is printed so a
failure can be replayed.  Two changes need a look:

- =pre-test-result= gained a =line= slot, and =make-pre-test-result= accepts
  =#:line=;
- the quoted =(comp ...)= family of deferred forms is replaced by =(lazy ...)=;
- a test result now records the file it was declared in, which reports write
  out.

Nothing else changed shape.

* Shuffling is still the default
:PROPERTIES:
:CUSTOM_ID: shuffle
:END:

A suite runs its children in a shuffled order unless it passes
=#:shuffle? #f=:

#+begin_src scheme
(suite "order independent" #:shuffle? #f
       (test "a" ...) (test "b" ...))
#+end_src

The shuffle uses one seed for the whole run.  The seed is printed at the end
(=shuffled with seed 757909024 (replay with VERITAS_SEED=757909024)=) and stored
in the report, so an order that failed can be reproduced exactly.
=VERITAS_SHUFFLE_FILES=true= (=--shuffle-files=) shuffles whole files as well.

* Lazy assertions use =lazy=
:PROPERTIES:
:CUSTOM_ID: lazy
:END:

An assertion evaluates =lazy= payloads when it runs, in the scope where they
were written:

#+begin_src scheme
(assert-equal #:expect 2 #:got (lazy (+ 1 1)) #:timeout 5)
#+end_src

The quoted list forms =(comp ...)=, =(compute ...)= and =(computare ...)= are
gone: they were evaluated with =eval= in the interaction environment, which lost
the lexical scope around them and compiled the expression at run time.  Wrap the
expression in =(lazy ...)= instead.  It is forced afresh by each assertion that
receives it, so nothing is cached, and it runs inside the assertion's deadline.
=#:expect= accepts it as well.

* Test results carry a line
:PROPERTIES:
:CUSTOM_ID: results
:END:

=make-pre-test-result= gained =#:line=, beside =#:file= and =#:duration=:

#+begin_src scheme
(make-pre-test-result name results #:file "test/foo.scm" #:line 42)
#+end_src

The positional constructor is unchanged apart from the extra slot, and the
accessors =pre-test-result-file=, =pre-test-result-line= and
=pre-test-result-duration= are the supported way to read a result.

Guile 3.0 does not expose a syntax object's line, so =#:line= is only filled in
when a caller supplies it.  Files are captured automatically, from the
declaration site or, failing that, from the file the runner is reading.

* Summary of breaking changes
:PROPERTIES:
:CUSTOM_ID: breaking
:END:

| Change                                   | Why                                                        |
|------------------------------------------+------------------------------------------------------------|
| =(comp ...)= lists removed               | =(lazy ...)= keeps lexical scope and needs no =eval=        |
| =pre-test-result= has a =line= slot      | a failure should be clickable in an editor                 |
| JUnit cases carry =file= and =line=      | CI annotations need a source position                      |

Additive, not breaking: =veritas-clock=, =veritas-current-location=,
=docs/=, =bench/bench.scm=, the JUnit schema at =test/veritas/junit.xsd=.
Suite shuffling is unchanged: still the default, still seeded and replayable.
