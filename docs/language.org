* Tests and suites
:PROPERTIES:
:CUSTOM_ID: tests
:END:

=(test name body ...)= declares one test.  =(suite name body ...)= groups tests
and other suites; a nested suite's name is joined with its parents in reports
(=outer > inner=).

Both accept the same keywords:

| Keyword        | Meaning                                                      |
|----------------+--------------------------------------------------------------|
| =#:skip?=      | mark it skipped; the body still has to parse                  |
| =#:tags=       | a list of tags, for filtering                                 |
| =#:timeout=    | seconds before the body is abandoned                          |
| =#:before=     | thunk run before the test or suite                            |
| =#:after=      | thunk run after it, even if it failed                         |
| =#:shuffle?=   | shuffle this suite's children (=#t= by default; the seed is reported) |
| =#:concurrent?=| run a suite's children in parallel fibers (=#t= by default)    |
| =#:before-all= | run once before a suite's children                            |
| =#:after-all=  | run once after them, even if some failed                      |

Declaring a test is cheap: the body forms are wrapped in thunks and nothing else
happens until the test runs.  See [[file:internals.org][How veritas works]].

* What a body may be
:PROPERTIES:
:CUSTOM_ID: bodies
:END:

A test body is usually assertions.  Two shorthands exist:

- a procedure is called with the run context, and its assertions are collected;
- any other value is asserted to be true, so =(test "yes" #t)= passes and
  =(test "no" #f)= fails.

A body that raises is reported as an error with its message, not as a crash of
the run.  A test with no assertions is reported as =no assertions=, so a typo
does not look like a pass.

* Assertions and matchers
:PROPERTIES:
:CUSTOM_ID: assertions
:END:

All assertions take =#:name= (a label for the report) and =#:timeout=.

| Assertion                                | Passes when                                  |
|------------------------------------------+----------------------------------------------|
| =(assert #:expect E #:got G)=            | =E= and =G= are =equal?=                      |
| =(assert-equal #:expect E #:got G)=      | the same, named for readability               |
| =(assert-true #:got G)=                  | =G= is true                                   |
| =(assert-false #:got G)=                 | =G= is false                                  |
| =(assert-null #:got G)=                  | =G= is the empty list                         |
| =(assert-not-null #:got G)=              | =G= is not                                    |
| =(assert-contains #:expect C #:got X)=   | =C= contains =X= (string, list, vector, table)|
| =(assert-not-contains ...)=              | it does not                                  |
| =(assert-match #:pattern P #:got G)=     | =G= matches the =(ice-9 match)= pattern =P=  |
| =(assert-error #:expect thunk)=          | =thunk= raises                                |
| =(assert-no-error #:expect thunk)=       | it does not raise                             |
| =(assert-greater-than ...)=, =(assert-less-than ...)= | the obvious                       |
| =(assert-length-of #:expect n #:got C)=  | the length matches                            |

Work that should happen when the assertion runs, rather than when it is
written, is wrapped in =lazy=:

#+begin_src scheme
(assert-equal #:expect 2 #:got (lazy (expensive-sum 1 1)) #:timeout 5)
#+end_src

=lazy= keeps the lexical scope of the expression, is evaluated once per
assertion that receives it (nothing is cached), and runs inside the assertion's
=#:timeout=, so a deadline can interrupt it.  It works for =#:expect= as well as
=#:got=.

Failure messages are stable text: =expect: ..., got: ...= for a mismatch,
=error, ...= when the comparison itself raised.  A failing =assert-equal= adds a
line saying where the values first differ:

#+begin_src scheme
error, expect: (1 2 3), got: (1 2 9)
  lists differ at index 2 (expected 3, got 9); lengths 3 and 3
#+end_src

Strings are compared character by character the same way.  Snapshot tests can
compare the messages.

=assert-match= takes its pattern from =(ice-9 match)=: rest patterns such as
=(a b ...)=, predicates such as =(? even?)=, literals and quoted patterns all
work.  Both =#:pattern (a b ...)= and =#:pattern '(a b ...)= are read as the
pattern itself.

* Timeouts
:PROPERTIES:
:CUSTOM_ID: timeouts
:END:

=#:timeout= on a test or an assertion bounds how long its body may take, in
seconds.  A timeout is reported as a failure with the time it waited, not as an
error of the run.

* Behaviour-driven style
:PROPERTIES:
:CUSTOM_ID: bdd
:END:

=describe=, =context= and =it= are aliases of =suite= and =test=, so a suite
can read as prose without changing how it is reported.

* Data-driven tests
:PROPERTIES:
:CUSTOM_ID: data
:END:

=for-each-test= runs one body for every row of a list, naming each run after the
row:

#+begin_src scheme
(for-each-test (list 1 2 3)
  (lambda (n)
    (assert-true #:got (> n 0))))
#+end_src

* Test doubles
:PROPERTIES:
:CUSTOM_ID: doubles
:END:

=make-stub= returns a procedure that returns a fixed value and remembers its
calls; =make-spy= wraps a real procedure and records the arguments it received.
=with-doubles= installs a set of doubles for the dynamic extent of its body and
restores the originals afterwards, so a double cannot leak into another test.

* Snapshots
:PROPERTIES:
:CUSTOM_ID: snapshots
:END:

=(assert-snapshot #:name "the report" #:got text)= compares =text= with the
snapshot of that name, writing it the first time.  Set
=VERITAS_UPDATE_SNAPSHOTS=true= to accept a change.  Snapshots are ordinary
files under =test/snapshots=, so they are reviewable in a diff.

* Generators
:PROPERTIES:
:CUSTOM_ID: generators
:END:

=property= checks one assertion against many generated inputs:

#+begin_src scheme
(property "reverse of reverse is the original list"
          #:generators (list (generate-list (generate-integer)))
          #:thunk (lambda (xs)
                    (assert-equal #:expect xs
                                  #:got (reverse (reverse xs)))))
#+end_src

The thunk runs 100 times by default; =#:runs= sets the count, =#:seed= makes the
draw reproducible, and =#:shrink? #f= turns shrinking off.  A failing input is
shrunk to the smallest value from the same generators that still fails, and the
report names the original and the shrunk value.  The seed printed with the
failure replays it: set =VERITAS_SEED= to that seed.

Generators are procedures of a random state, so they compose:

| Generator                                   | Draws                             |
|---------------------------------------------+-----------------------------------|
| =(generate-integer #:max-bound 100)=        | an integer below the bound        |
| =(generate-natural #:max-bound 100)=        | an integer up to and including it |
| =(generate-real #:min 0 #:max 1)=           | a real number in the range        |
| =(generate-boolean)=                        | =#t= or =#f=                      |
| =(generate-char)=                           | a printable ASCII character       |
| =(generate-string #:min-len 1 #:max-len 8)= | a printable ASCII string          |
| =(generate-symbol #:min-len 1)=             | a lowercase symbol                |
| =(generate-list gen #:min-len 0)=           | a list of generated elements      |
| =(generate-vector gen #:min-len 0)=         | a vector of them                  |
| =(generate-tuple (list gen ...))=           | one value from each generator     |
| =(generate-one-of '(a b c))=                | one of the choices                |
| =(generate-constant value)=                 | the value                         |

Fake data is one generator call away, for a report that reads like a report:

| Generator               | Draws                     |
|-------------------------+---------------------------|
| =(generate-first-name)= | =Ada=, =Grace=, ...       |
| =(generate-last-name)=  | =Lovelace=, =Hopper=, ... |
| =(generate-name)=       | a first and a last name   |
| =(generate-email)=      | =first.last@example.com=  |
| =(generate-beer)=       | a beer style              |
| =(generate-car)=        | a make and model          |

The built-in generators shrink their values: integers toward zero, strings and
lists to shorter ones, booleans to =#f=.  =generator-shrink= returns the
candidates a value has, and a generator written by hand simply does not shrink.
