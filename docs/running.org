* Discovery
:PROPERTIES:
:CUSTOM_ID: discovery
:END:

=veritas= with no argument reads the current directory; with a file it runs
that file; with a directory it walks it.  Files are grouped by test type: a
=unit= run reads =test/*/unit/*.scm=, an =integration= run reads
=test/*/integration/*.scm=, and =VERITAS_TEST_TYPE= (or =--test-type=) selects
one.

Files are sorted by path before they run, so discovery never depends on the
order a filesystem hands directory entries back.  Each file is loaded in its own
module and its exported entry point (default =spec=) is called; nothing runs at
import time.

* Order, shuffling and seeds
:PROPERTIES:
:CUSTOM_ID: order
:END:

A suite shuffles its tests by default: shuffling exposes an order dependency
instead of hiding it.  Pass =#:shuffle? #f= to keep declaration order, or set
=VERITAS_SHUFFLE_FILES=true= (=--shuffle-files=) to shuffle the files too.  Both
use one seed for the run, printed at the end and stored in reports, so an order
can be replayed with =VERITAS_SEED=.

See [[file:migration.org][Migration guide]].

* Parallel runs
:PROPERTIES:
:CUSTOM_ID: workers
:END:

=--jobs N= runs files in N worker processes; each writes its own JUnit
fragment, and the parent merges them into one document (see
[[file:reporting.org][Reports and diagnostics]]).  Within a file, a suite with
=#:concurrent? #t= runs its children in fibers.  Set
=#:concurrent? #f= when the tests share mutable state.

Determinism under concurrency: results are collected per task and reported in
declaration order, not in completion order, so a parallel run and a serial run
of the same suite produce the same report apart from timings.

* Rerunning only what failed
:PROPERTIES:
:CUSTOM_ID: rerun
:END:

Every run writes the names of the tests that failed to
=reports/last-failed.scm=, or an empty list when everything passed.  That record
is what =--only-failed= reads, and nothing else is run:

#+begin_src sh
veritas --only-failed            # the tests that failed last time
veritas --only-failed --jobs 4   # the same, in parallel
#+end_src

The record is plain Scheme data, one line of names:

#+begin_src scheme
("a string holds a word" "two and two")
#+end_src

An empty record is still a record: after a green run =--only-failed= selects
*nothing* rather than everything, so a retry of a passing suite stays green and
fast.  A run with no record at all - the first run in a fresh checkout - selects
everything, because there is nothing to narrow it to.

A failure that carries no test name, such as a task that raised while the file
was loading, is recorded as =#all=: the next run reruns everything, because no
name describes what went wrong.  With =--jobs= each worker records its own
failures and the parent merges them, so the record after a parallel run is the
same as after a serial one.

Set =VERITAS_LAST_FAILED_PATH= to keep the record somewhere else, which is what
a build that shares a checkout between jobs needs.  A test that is still failing
is rewritten into the record by the run that reran it, so the loop below walks
the suite down to green:

#+begin_src sh
until veritas --only-failed; do :; done
#+end_src

* Coverage
:PROPERTIES:
:CUSTOM_ID: coverage
:END:

=--coverage= (or =VERITAS_COVERAGE=true=) instruments the files under
=VERITAS_COVERAGE_INCLUDE= (default: the current directory), minus
=VERITAS_COVERAGE_EXCLUDE=, and writes LCOV to =VERITAS_COVERAGE_DIR= (default
=reports/lcov=) plus an HTML report to =VERITAS_COVERAGE_HTML_DIR= (default
=reports/html=).  Coverage data is reported per file, sorted by path.
